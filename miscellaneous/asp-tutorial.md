# ASP 教学：从语法到建模实战

## 0. 这份文档是什么

本仓库的数墙求解器中有一个 `AspSolver`——把数墙规则写成 ASP 程序，交给 clingo 求解。ASP（Answer Set Programming，回答集编程）的思维方式与命令式编程完全不同：**你描述"解应该满足什么"，而不是"怎么一步步算出来"**。本教程从零开始，把 ASP 的语法（每个 token 的含义）、求解原理和建模思路讲清楚，并用数独、数墙两个完整例子演示**为什么要那样写**。

文中所有程序都经过 clingo 5.8 实际运行验证，可以复制到本机直接执行。运行需要安装 clingo（安装方法见《[ASP 规约解题](ASP%20规约解题.md)》第 7 节）。

与《ASP 规约解题》的分工：那份文档回答"ASP 是什么、为什么快、和 SAT/SMT 比怎么样"；本文只做教学——**语法逐个讲解 + 完整建模演示**。仓库里 `AspSolver` 的实际代码见 `src/Nurikabe/Nurikabe.Core/Solving/AspSolver.cs`，其内嵌的 ASP 程序与本文第 6 节完全一致。

## 1. 先把程序跑起来

新建文件 `hello.lp`：

```prolog
a.
b :- a.
c.
```

运行：

```bash
clingo hello.lp
```

输出（节选）：

```
Solving...
Answer: 1
a b c
SATISFIABLE

Models       : 1
```

逐行解读：

- `a.` 是**事实**（fact）：无条件为真的陈述。
- `b :- a.` 是**规则**（rule）：读作"若 `a` 为真，则 `b` 为真"。冒号加横线 `:-` 就是规则箭头，箭头左边是**结论**，右边是**条件**。
- clingo 输出的 `Answer: 1` 是一个**回答集**（answer set）——满足全部事实与规则的真原子集合。**一个回答集 = 一个问题的一个解**。这里的回答集是 `{a, b, c}`（三个原子全为真，`b` 由规则推出）。
- `SATISFIABLE` 表示有解；若程序互相矛盾则输出 `UNSATISFIABLE`。

两点值得先记住：

1. **规则是约束，不是赋值语句**。`b :- a.` 不"计算" `b`，它声明"任何让 `a` 为真而 `b` 不为真的候选都被排除"。
2. **求解是搜索，不是执行**。clingo 会自己尝试所有可能性，直到找到满足全部规则的真原子集合。

命令行常用参数：

| 参数 | 含义 |
|------|------|
| `clingo 文件.lp` | 求解（默认只找 1 个解） |
| `clingo -n 0 文件.lp` | 枚举全部解（`--models=0` 同义） |
| `clingo --text 文件.lp` | 不求解，只输出接地后的程序（见第 3 节） |
| `clingo --stats 文件.lp` | 输出求解时间统计 |
| `clingo -c N=7 文件.lp` | 覆盖程序中的 `#const N = 7.` |
| `clingo 事实.lp 规则.lp` | 多个文件按顺序拼接为一个程序 |

脚本中判断结果可以看退出码：`echo $?`——**30 = 有解（SATISFIABLE），20 = 无解（UNSATISFIABLE），10 = 未知（超时/中断）**。

## 2. 语法逐项精讲

这一节把 ASP 的每个语法要素讲透，是本教程的核心。所有例子都可以独立运行。

### 2.1 注释

`%` 开始的行注释和 `/* */` 块注释，与 C 系语言一致。

```prolog
% 这是行注释
/* 这是
   块注释 */
```

### 2.2 项（term）：常量、变量、数字

项是程序的最小组成单位，三种形态：

| 形态 | 例子 | 说明 |
|------|------|------|
| 常量 | `tweety`、`ann`、`3` | 小写字母开头；数字本身就是常量 |
| 变量 | `X`、`R`、`RootC` | **大写字母开头**。同一规则中同名变量代表同一个值 |
| 函数项 | `f(1, X)`、`(R-1)/3` | 函数/算术应用，接地时求值 |

### 2.3 原子（atom）与谓词

`bird(tweety)` 是一个原子：**谓词** `bird` 加**参数** `tweety`。参数的个数叫**元数**（arity），写作 `bird/1`。原子在回答集中非真即假——这就是 ASP 里的"变量"，只不过它们不叫变量，叫原子。

### 2.4 事实：以句号结尾的恒真陈述

```prolog
p.            % 无参数的原子
bird(tweety). % 一个参数
num(1..9).    % 区间：等价于 num(1). num(2). ... num(9).
```

`1..9` 是**区间**（range）语法：批量生成连续整数。定义"数字的取值域"全靠它。

### 2.5 规则：`结论 :- 条件1, 条件2.`

```prolog
flies(X) :- bird(X), not penguin(X).
```

- 读作：**如果体（右边）全部成立，则头（左边）成立**。
- 逗号 `,` 是**逻辑与**：所有条件要同时满足。
- 箭头为什么反着写？规则源于逻辑蕴含 `bird(X) → flies(X)`。ASP 的惯例是把结论写在左、条件写在右，中间用 `:-` 连接。记住**头是结论、体是条件**即可。
- 规则隐含**全称量化**：一条规则对变量的一切取值都适用，接地时把变量替换成具体常量。

**安全变量（safety）**：规则中的每个变量**必须至少出现在一个正的（不带 `not` 的）体文字里**，否则接地会无穷展开。比如 `q(X).`（变量出现在头但体为空）就无法接地，clingo 会报 `unsafe variable`。这条规则保证了接地后的程序永远是有限的。

### 2.6 约束：`:- 条件.`——头为空

规则的头可以省略，得到**约束**（constraint）：

```prolog
a.
:- a.   % 禁止 a 为真
```

运行结果是 `UNSATISFIABLE`：事实要求 `a` 为真，约束禁止 `a` 为真，自相矛盾，无解。

约束是 ASP 建模中使用最频繁的工具。读作：**禁止条件成立**。建模套路是：先用选择规则"生成"一大堆候选，再用约束把不合规矩的候选全部砍掉（详见第 4 节）。

### 2.7 否定为失败：`not`

```prolog
bird(tweety).
bird(polly).
penguin(polly).

flies(X) :- bird(X), not penguin(X).
```

运行结果：

```
Answer: 1
bird(tweety) bird(polly) penguin(polly) flies(tweety)
```

`tweety` 会飞，`polly` 不会——因为 `penguin(polly)` 能被证明，而 `penguin(tweety)` 不能。

`not p` 的含义是 **p 无法被推导为真**（negation as failure，否定为失败）。这与经典逻辑的"非"有本质区别：经典"非 p"需要知道 p 为假；`not p` 只是"没有证据证明 p 为真，就默认 p 为假"。它是**非单调**的：往程序里加一条事实，可能让原来成立的结论消失（比如补上 `penguin(tweety).` 后 `flies(tweety)` 就没了）。

在谜题建模里 `not` 有两大用途：

1. **默认推理**："鸟会飞，企鹅除外"——只描述例外，其余默认成立。
2. **排除**：数独的"已知数字"约束 `:- puzzle(R, C, N), not cell(R, C, N).`——若格子没有填成题目要求的数字，则解作废。

### 2.8 选择规则与基数约束：`{ }`

```prolog
1 { a; b; c } 2.
```

- `{ }` 内用分号 `;` 列出可选的原子，左右两个数字是**下界**和**上界**。
- 读作：**从 {a, b, c} 中选取 1 到 2 个为真**。

运行 `clingo -n 0` 枚举全部解，得到 6 个回答集：`{b}`、`{a}`、`{a,b}`、`{c}`、`{a,c}`、`{b,c}`——恰好是 1 选 1、1 选 2 的所有组合。

不带边界的 `{ a; b; c }.` 表示 0 到无穷任意选；`1 { a; b; c } 1` 就是**恰好选一个**。

选择规则是 ASP 建模的第一块基石：它**声明搜索空间**——"哪些原子是候选、每个候选可以取什么值"。命令式语言里你要写 `for` 循环枚举，ASP 里一句选择规则就完成了。

**带条件的集合**（谜题建模中最常用的形态）：

```prolog
1 { cell(R, C, N) : num(N) } 1 :- row(R), col(C).
```

冒号 `:` 是**条件语法**：`{ cell(R,C,N) : num(N) }` 表示"对每个 N（N 遍历 num/1 的所有实例），`cell(R,C,N)` 都是候选"。整句读作：**对每个格子，恰好选一个数字填入**。不用把 9 个原子手写出来，也不限于 9——改成 `num(1..16)` 就是 16 种候选。

### 2.9 聚合：`#count`、`#sum`、`#min`、`#max`

```prolog
person(ann). person(bob). person(cyn).
item(a, 2). item(b, 3). item(c, 5).

num_people(N) :- N = #count { P : person(P) }.
total(S)      :- S = #sum { V : item(_, V) }.
```

运行得到 `num_people(3)` 和 `total(10)`。

- `#count { X : p(X) }`：满足条件 `p(X)` 的 X 的数量。
- `#sum { V : ... }`：求和（每个元素可带权重，`#sum` 的用法是 `#sum { V : p(V) }` 对 V 求和）。
- `_` 是**匿名变量**：`item(_, V)` 中 `_` 匹配任何值但无需命名；每个 `_` 互相独立。

聚合最强大的用法是放进约束里与比较组合：

```prolog
:- row(R), num(N), #count { C : cell(R, C, N) } != 1.
```

读作：**对每行每数字，若出现次数不等于 1，则该回答集作废**——一句就完成了"行内数字不重复"。比起手写"任意两格不相等"的成对约束（`:- row(R), cell(R,C1,N), cell(R,C2,N), C1 < C2.`），聚合既简短又直白，接地规模还小。

### 2.10 算术与比较

```prolog
num(1..4).

even(X) :- num(X), X \ 2 == 0.   % X 除以 2 余 0（\ 是取模）
mid(X)  :- num(X), X > 1, X < 4.

double(D, X) :- num(X), D = X * 2.
```

运行得到：`even(2)`、`even(4)`、`mid(2)`、`mid(3)`、`double(2,1)`、`double(4,2)`、`double(6,3)`、`double(8,4)`。

要点：

- 算术项（`X * 2`、`R+1`、`(R-1)/3`）在**接地时求值**——变量先被绑定为具体数字，再代入计算。
- 比较运算（`<` `<=` `>` `>=` `==` `!=`）只能出现在规则体里，作用类似筛选条件。
- **`=` 是赋值/合一，`==` 是比较**：`D = X * 2` 把算出的值绑定给 `D`；`X == 0` 只做相等判断。写错会得到难查的错误。

### 2.11 输出过滤：`#show`

不加 `#show` 时，clingo 输出**全部**为真的原子——包括辅助谓词，非常吵。`#show black/2.` 只输出元数为 2 的 `black` 原子（`/2` 表示元数）。一个程序可以有多个 `#show`。

### 2.12 token 速查表

| 记号 | 含义 | 示例 |
|------|------|------|
| `.` | 语句结束符 | `a.` |
| `:-` | 规则箭头（左结论右条件）；头为空 = 约束 | `b :- a.`、`:- a.` |
| `,` | 且（体内的多个条件） | `h :- a, b.` |
| `;` | 选择规则中的备选；体内也可表"或" | `1 { a; b } 1` |
| `not` | 否定为失败（无法证明则为假） | `not penguin(X)` |
| `{ }` | 选择规则（生成候选） | `1 { a; b } 2` |
| `:` | 条件语法（冒号后是作用域/条件） | `cell(R,C,N) : num(N)` |
| `..` | 区间 | `1..9` |
| `_` | 匿名变量（每次出现独立） | `number(R, C, _)` |
| `=` | 赋值/合一（把值绑定给变量） | `D = X * 2` |
| `==` `!=` `<` `<=` `>` `>=` | 比较（只能出现在体内） | `R2 < R` |
| `+ - * / \` | 算术（`\` 为取模，`/` 为整除） | `(R-1)/3` |
| `%` `/* */` | 注释 | |
| `#count` `#sum` `#min` `#max` | 聚合 | `#count { C : cell(R,C,N) }` |
| `#show p/2.` | 只输出指定原子 | `#show black/2.` |
| `#const N = 7.` | 常量（命令行 `-c N=7` 可覆盖） | |
| 小写开头 | 常量 | `tweety` |
| 大写开头 | 变量（同一规则内同名同值） | `X` |

## 3. 接地与求解：clingo 内部发生了什么

clingo 求解分两个阶段：

1. **接地（grounding，gringo）**：把带变量的规则展开成无变量的命题实例——就是 2.5 节"全称量化"的具体化。
2. **求解（solving，clasp）**：在接地后的程序上搜索回答集（本质是带稳定模型语义的 CDCL SAT 求解器）。

`clingo --text` 可以查看接地结果。用 2×2 数墙程序（邻接 + 二选一）演示：

```prolog
dim(2,2).
number(1,1,1).

row(1..N) :- dim(N, _).
col(1..M) :- dim(_, M).
cell(R, C) :- row(R), col(C).

adj(R, C, R+1, C) :- cell(R, C), cell(R+1, C).
adj(R+1, C, R, C) :- cell(R, C), cell(R+1, C).
adj(R, C, R, C+1) :- cell(R, C), cell(R, C+1).
adj(R, C+1, R, C) :- cell(R, C), cell(R, C+1).

1 { black(R, C); white(R, C) } 1 :- cell(R, C), not hollowed(R, C).
white(R, C) :- number(R, C, _).
```

运行 `clingo --text`，输出（节选）：

```
dim(2,2).
number(1,1,1).
white(1,1).
col(1).
col(2).
row(1).
row(2).
cell(1,1).
cell(2,1).
cell(1,2).
cell(2,2).
adj(1,2,1,1).
adj(2,2,2,1).
adj(1,1,1,2).
adj(2,1,2,2).
adj(2,1,1,1).
adj(2,2,1,2).
adj(1,1,2,1).
adj(1,2,2,2).
#delayed(1) <=> 1>=#count{0,white(1,1):#true;0,black(1,1):black(1,1)}
#delayed(2) <=> 1<=#count{0,white(2,1):white(2,1);0,black(2,1):black(2,1)}<=1
#delayed(3) <=> 1<=#count{0,white(1,2):white(1,2);0,black(1,2):black(1,2)}<=1
#delayed(4) <=> 1<=#count{0,white(2,2):white(2,2);0,black(2,2):black(2,2)}<=1
```

观察几点：

- 事实原样保留；`row(1..N) :- dim(N, _)` 展开成了 `row(1). row(2).`——变量的每个取值对应一个实例。
- 邻接的 4 条规则展开成 8 个 `adj` 实例（每个相邻对一条，含两个方向）。
- `white(1,1)` 由 `white(R,C) :- number(R,C,_)` 推出（数字格必为陆）。
- 选择规则被转成 `#delayed(...) <=> ...` 的形式——`#delayed` 是 clingo 内部的延迟约束辅助原子，不必深究。有意思的是 (1,1) 的约束被**化简**了：`white(1,1)` 已是事实（标记 `#true`），"恰好一个"退化为"至多一个"（`1>=#count`）；其余格子保持完整的 `1<=...<=1`。这就是传播的雏形——**已知的信息越多，约束越简单**。

为什么要理解接地？

- **性能问题先分接地还是求解**：`--stats` 会分别报告 Grounding 和 Solving 时间。
- **"安全变量"规则的根本原因**：接地规模必须有限。
- **一条规则 ≠ 一个实例**：写规则时心里要有数——它会被展开多少倍（第 6.1 节会看到 4 条 vs 两两比较的接地规模差异）。

## 4. 建模方法论：生成-检验（generate-and-test）

几乎所有逻辑谜题的 ASP 编码都是同一个三步套路：

1. **事实**：题目实例——盘面尺寸、已知数字。
2. **生成**：选择规则声明搜索空间——每个格子有哪些候选状态。
3. **检验**：约束砍掉违反规则的候选——连通性、唯一性、面积、邻接限制。

```prolog
% 1. 事实（题目）
dim(5,5).

% 2. 生成（候选）
1 { black(R, C); white(R, C) } 1 :- cell(R, C).

% 3. 检验（约束）
:- black(R, C), black(R+1, C), black(R, C+1), black(R+1, C+1).  % 禁止 2x2 海
```

值得注意：命令式语言里"验证一个解是否合法"（`IsSolved`）和"求出解"（求解器）是两段代码；在 ASP 里**它们就是同一份程序**——约束既用于生成后的检验，也用于求解时的剪枝。这正是声明式编程的核心：只描述"解是什么"，解法的搜索完全交给求解器。

下面两个完整演示都按这三步展开。

## 5. 完整演示一：数独

### 5.1 题目

经典 9×9 数独（`.` 表示空格）：

```
5 3 . | . 7 . | . . .
6 . . | 1 9 5 | . . .
. 9 8 | . . . | . 6 .
------+-------+------
8 . . | . 6 . | . . 3
4 . . | 8 . 3 | . . 1
7 . . | . 2 . | . . 6
------+-------+------
. 6 . | . . . | 2 8 .
. . . | 4 1 9 | . . 5
. . . | . 8 . | . 7 9
```

### 5.2 建模：逐步解释为什么这样写

**第 1 步：领域事实。**

```prolog
row(1..9).
col(1..9).
num(1..9).
```

三个区间把行、列、数字的取值域一次性定义好。所有后续规则都引用这些谓词——想改成 4×4 数独，只需把 9 改成 4，其余一字不动。

**第 2 步：题目事实。**

```prolog
puzzle(1,1,5). puzzle(1,2,3). puzzle(1,5,7).
puzzle(2,1,6). puzzle(2,4,1). puzzle(2,5,9). puzzle(2,6,5).
...（其余已知数字）
```

每个已知数字一条事实。注意 `puzzle/3` 与最终的 `cell/3` 是**不同的谓词**——题目输入和搜索变量分开，规则才不会被事实"污染"。

**第 3 步：生成——每格恰好一个数字。**

```prolog
1 { cell(R, C, N) : num(N) } 1 :- row(R), col(C).
```

为什么用带条件的基数约束而不是手写 9 个原子的选择规则？候选集合由 `num/1` 驱动：要支持 16×16 数独，只改 `num(1..16)` 一处。更根本的是——**"每格恰好一个值"这类互斥选择正是基数约束的本命**，下界上界都是 1，一句话完成"恰好一个"。

**第 4 步：行、列内不重复。**

```prolog
:- row(R), num(N), #count { C : cell(R, C, N) } != 1.
:- col(C), num(N), #count { R : cell(R, C, N) } != 1.
```

为什么用 `#count` 而不用"任意两格不等"的成对约束？两种写法语义等价，但成对版本要枚举 `C1 < C2` 的所有组合（每行 36 对），接地规模大、读起来绕；聚合一行就把"恰好一次"说清楚了。聚合与 `!=` 组合是"唯一性"约束的标准写法。

**第 5 步：宫（3×3 子块）内不重复。**

```prolog
subgrid(SG_R, SG_C, R, C) :-
    row(R), col(C),
    SG_R = (R - 1) / 3,
    SG_C = (C - 1) / 3.

:- num(N), subgrid(SG_R, SG_C, _, _),
   #count { R, C : cell(R, C, N), subgrid(SG_R, SG_C, R, C) } != 1.
```

为什么先写一条 `subgrid/4` 派生规则？把"每个格子属于哪个宫"**显式算出来**，约束里只需引用。`(R-1)/3` 是整数除法：R ∈ 1..9 时结果为 0、1、2，恰好把 9 行分成 3 组；行、列各分 3 组，组合出 9 个宫。

约束的写法：`subgrid(SG_R, SG_C, _, _)` 枚举全部 9 个宫（`_, _` 是匿名变量，我们只关心宫的编号），`#count` 的条件里同时要求 `cell(R,C,N)` 且该格属于当前宫——"每个数字在每宫恰好出现一次"。

**第 6 步：服从已知数字。**

```prolog
:- puzzle(R, C, N), not cell(R, C, N).
```

读作：若题目要求 `(R,C)` 填 N，而 `cell(R,C,N)` 不为真，则解作废。这就是 2.7 节的"排除"用法——`not` 砍掉所有没填对的候选。

为什么用排除而不是直接推导 `cell(R, C, N) :- puzzle(R, C, N).`？两条路都对。直接推导更"省事"，但把它写成约束保持了三步法的对称性：**生成只由选择规则负责，检验只由约束负责**——每类代码职责单一，后续调试时思路清晰。仓库的 `AspSolver` 里两种风格并存：数字格强制为陆用的是推导（`white(R, C) :- number(R, C, _).`，见 6.2），其余规则一律走约束——推导用于"必然成立"的简单事实，约束用于"排除不合法候选"的复杂判定。

**第 7 步：输出。**

```prolog
#show cell/3.
```

不加这行，`puzzle/3`、`subgrid/4` 的原子也会全打出来。

### 5.3 完整程序

```prolog

puzzle(2,1,6). puzzle(2,4,1). puzzle(2,5,9). puzzle(2,6,5).
```

## 6. 完整演示二：数墙（Nurikabe）

数墙规则（详见 `docs/Nurikabe/数墙_基本设定和规则.md`）：

1. 每个数字是一个岛屿的"岛主"，岛屿面积必须恰好等于数字值；
2. 岛屿之间不能相邻（上下左右）；
3. 所有海方块（非岛屿格）必须连成一片；
4. 任何 2×2 的格子不能全是海。

用仓库 `ConsoleTest` 里的一道 7×7 题目（`7:7:03(1);06(2);11(1);23(1);41(2);43(2);46(5);60(4);64(2):::`）演示。题目字符串中数字方块用**双字符坐标**：每坐标两个字符（行、列各一，0 基），所以 `03(1)` 表示第 0 行第 3 列（即第 1 行第 4 列）有一个数字 1。转成 ASP 事实：

```prolog
%  03(1)  06(2)  11(1)  23(1)  41(2)  43(2)  46(5)  60(4)  64(2)
dim(7,7).
number(1,4,1). number(1,7,2). number(2,2,1). number(3,4,1).
number(5,2,2). number(5,4,2). number(5,7,5). number(7,1,4). number(7,5,2).
```

这个 ASP 程序与仓库 `AspSolver` 内嵌的 `ConstraintsClingoCodeSnippet` 完全一致（`AspSolver` 只是把盘面自动转成上面的 `dim/2`、`number/3` 事实）。

### 6.1 网格与邻接

```prolog
row(1..N) :- dim(N, _).
col(1..M) :- dim(_, M).
cell(R, C) :- row(R), col(C).

adj(R, C, R+1, C) :- cell(R, C), cell(R+1, C).
adj(R+1, C, R, C) :- cell(R, C), cell(R+1, C).
adj(R, C, R, C+1) :- cell(R, C), cell(R, C+1).
adj(R, C+1, R, C) :- cell(R, C), cell(R, C+1).
```

- `cell/2` 定义"格子存在"。用 `dim(N, _)` 展开出行列，再交叉出全部格子——棋盘大小由事实驱动，程序本身与尺寸无关。
- `adj/4` 定义上下左右相邻。**为什么写 4 条而不是一条"两两比较"？** 对比写法 `adj(A1,B1,A2,B2) :- cell(A1,B1), cell(A2,B2), |A1-A2| + |B1-B2| == 1.` 语义相同，但要先把**所有格子对**接地（7×7 是 2401 对）再筛选；4 条规则只对接地实际相邻的格子对（每边一条），7×7 是 84 个实例，接地规模小一个量级。
- **为什么两个方向都要**？`adj` 用于可达性传播，必须双向。两条规则（`(R,C)-(R+1,C)` 和 `(R+1,C)-(R,C)`）的体完全相同，只是参数顺序交换——无向图的邻接在 ASP 里就是两条有向规则的并集。

### 6.2 海/陆二选一

```prolog
1 { black(R, C); white(R, C) } 1 :- cell(R, C), not hollowed(R, C).
white(R, C) :- number(R, C, _).
```

第一句是**生成**：每个非挖去格恰好是海（`black`）或陆（`white`）之一。第二句是**强制**：数字格必须是陆。

为什么要写成选择规则，而不是"先选海、陆地由否定推出"（`white(R,C) :- cell(R,C), not black(R,C).`）？两种写法语义等价，但选择规则明显更好：

1. **可推广**：数独的九选一无法用 `not` 表达（`not black` 只能产生"非黑即白"的二分）；选择规则天然支持多值候选（`1 { cell(R,C,1); ...; cell(R,C,9) } 1`）。
2. **语义对称**：陆和海是**两个都要猜**的状态。用 `not` 写法时 `white` 变成"不是海的派生结论"，掩盖了"陆地同样是搜索变量"这一事实。
3. **职责清晰**：选择规则 = 搜索变量，派生规则 = 推理结论。后续所有约束引用 `white` 时，你知道它是被"生成"的；而 `white_reach`（见 6.4）是"派生"的。这个区分是读懂 ASP 程序的关键。

`not hollowed(R, C)` 把挖去格排除在选择之外——挖去格既不是海也不是陆，根本不出现在搜索空间里。

第二句 `white(R, C) :- number(R, C, _)` 是**检验的补充**。选择规则不知道数字格的特殊性，若不加这句，数字格可能被选为海——而岛屿可达性（6.4 的 `white_reach`）从数字格出发仍会蔓延，出现"数字漂在海里"的荒谬解。做个实验：删掉这句再求解 5×5 题目 `5:5:01(5);03(5):::`，立刻出现 `black(1,4)`、`black(1,2)`——**数字格被选成了海**，且求解器认为这合法。所以"数字格必为陆"必须显式声明。

（`_` 是匿名变量：`number(R, C, _)` 匹配任何数字值，反正这里不需要知道具体是几。）

### 6.3 禁止 2×2 海方块

```prolog
:- cell(R, C), cell(R+1, C+1),
   black(R, C), black(R+1, C),
   black(R, C+1), black(R+1, C+1).
```

读作：若以 `(R,C)` 为左上角的 2×2 全为海，则无解。

- **为什么只写左上角一个位置**：每个 2×2 方块有唯一的左上角，对全部格子实例化这条规则，就覆盖了所有 2×2 方块，不会重复也不会遗漏。
- **为什么列出 `cell(R,C)` 和 `cell(R+1,C+1)`**：把规则锚定在"格子确实存在"上——`(R+1, C+1)` 越界时该实例不接地。四个 `black` 原子其实已隐含了这些格子存在，但显式列出让意图一目了然，也让接地只发生在网格内。

### 6.4 岛屿：可达性、归属与面积

```prolog
white_reach(R, C, R, C) :- number(R, C, _).
white_reach(R2, C2, RootR, RootC) :-
    white_reach(R1, C1, RootR, RootC),
    white(R2, C2),
    adj(R1, C1, R2, C2).

:- white(R, C),
   #count { RootR, RootC : number(RootR, RootC, _),
                            white_reach(R, C, RootR, RootC) } != 1.

:- number(RootR, RootC, N),
   #count { R, C : white_reach(R, C, RootR, RootC) } != N.
```

**可达性（前两条）**：`white_reach(R, C, RootR, RootC)` 读作"格子 `(R,C)` 从数字 `(RootR,RootC)` 出发、只经过白格可达"。第一条是递归基：数字格自己可达自己（数字格必为白，无需再查 `white`）。第二条是递归步：如果 `(R1,C1)` 从某个根可达，且它的邻格 `(R2,C2)` 是白格，那么 `(R2,C2)` 也从同一个根可达。

- 这是标准的**传递闭包**写法——命令式语言里的 BFS/DFS，在 ASP 里就是两条递归规则。
- **为什么可达性要携带根坐标（`RootR, RootC`）**：岛屿规则要求"每个白格恰好属于一个数字"，这必须逐格记录"属于谁"才能用聚合检查。若只记 `reach(R,C)`（不带根），面积约束就写不出来——你无法按数字分组计数。
- **为什么这是派生谓词而不是选择**：`white_reach` 完全由 `white` 和 `number` 决定，不存在"猜测"。ASP 程序里要分清：**选择规则声明要猜什么，派生规则声明由此推出什么**——求解器只为前者做搜索。

**约束一（每个白格恰好一个根）**：`#count { RootR, RootC : number(...), white_reach(...) } != 1` 统计一个白格被多少个数字可达，不等于 1 就作废。**为什么必须有它？** 做个实验：删掉这条约束求解 5×5 题目，得到 4 个"解"（原本只有 1 个）：

```
Answer: 1
black(1,1) black(2,1) black(3,1) black(4,1) black(5,1) black(2,2)
black(5,2) black(3,3) black(4,3) black(5,3) black(3,4) black(5,4)
black(2,5) black(3,5) black(4,5) black(5,5) black(1,5)
```

这道题有两个数字 5（第 1 行第 2 列和第 1 行第 4 列）。这个"解"里白格只有 8 个，分成两块：一块 5 格**同时被两个数字 5 可达**——每个数字各计数 5，面积约束恰好通过！另有 3 个白格**没有任何数字可达**（无主孤岛）。岛屿被共享、被丢弃，面积却全对——这就是"归属"约束存在的意义：面积约束只保证数量，归属约束才保证**每个岛有且只有一个岛主**。

**约束二（面积精确匹配）**：`#count { R, C : white_reach(R, C, RootR, RootC) } != N` 按根分组数白格。注意这里统计的是 `white_reach` 而不是 `white`——`#count { R, C : white(R, C) }` 只数得全局白格总数，无法按数字区分；只有携带根的 `white_reach` 能回答"这个岛有几个格子"。

### 6.5 海方块全体连通

```prolog
has_smaller_black(R, C) :- black(R, C), black(R2, C2), R2 < R.
has_smaller_black(R, C) :- black(R, C), black(R, C2), C2 < C.
min_black(R, C) :- black(R, C), not has_smaller_black(R, C).

reach_black(R, C) :- min_black(R, C).
reach_black(R2, C2) :-
    reach_black(R1, C1),
    black(R2, C2),
    adj(R1, C1, R2, C2).

:- black(R, C), not reach_black(R, C).
```

"全体连通"是个整体性质，必须挑一个**种子**出发做传递闭包，然后要求每个海格都能从种子到达。

**为什么需要"字典序最小"技巧？** 若种子是自由选择的（比如 `{ seed(R,C) } :- black(R,C).`），同一个连通的海洋会对应**多个回答集**（选不同的格做种子），模型数量膨胀、求解变慢。所以种子必须**确定**——而"字典序最小的海格"就是一个确定的、可由规则计算的种子。

**为什么用两条 `has_smaller_black` 规则？** 第一条排除"有海格在更上面的行"的格子，第二条排除"同行有海格在更左列"的格子。两条合起来：`min_black` 就是**没有更早行、同行没有更左列**的海格——即字典序（先比行、同行比列）最小者。注意 `R2 < R` 同时作用于第一条件，`C2 < C` 只在同行比较，两条规则的体不同，缺一不可。（也可以用 `#min` 聚合写，但嵌套聚合的可读性不如这条朴素的排除法。）

随后的 `reach_black` 与 6.4 的 `white_reach` 是同构的传递闭包，最后一条约束杀掉"存在从种子不可达的海格"的回答集。这样"海连通"就从整体性质变成了逐格性质——这正是 ASP 能把图论性质写成规则的原因。

### 6.6 完整程序

```prolog
% ===== 题目事实（7×7，双字符坐标 0 基）=====
dim(7,7).
number(1,4,1). number(1,7,2). number(2,2,1). number(3,4,1).
number(5,2,2). number(5,4,2). number(5,7,5). number(7,1,4). number(7,5,2).

% ===== 1. 网格与邻接 =====
row(1..N) :- dim(N, _).
col(1..M) :- dim(_, M).
cell(R, C) :- row(R), col(C).

adj(R, C, R+1, C) :- cell(R, C), cell(R+1, C).
adj(R+1, C, R, C) :- cell(R, C), cell(R+1, C).
adj(R, C, R, C+1) :- cell(R, C), cell(R, C+1).
adj(R, C+1, R, C) :- cell(R, C), cell(R, C+1).

% ===== 2. 海/陆二选一 =====
1 { black(R, C); white(R, C) } 1 :- cell(R, C), not hollowed(R, C).
white(R, C) :- number(R, C, _).

% ===== 3. 禁止 2x2 海方块 =====
:- cell(R, C), cell(R+1, C+1),
   black(R, C), black(R+1, C),
   black(R, C+1), black(R+1, C+1).

% ===== 4. 岛屿 =====
% 可达性：携带根坐标的传递闭包
white_reach(R, C, R, C) :- number(R, C, _).
white_reach(R2, C2, RootR, RootC) :-
    white_reach(R1, C1, RootR, RootC),
    white(R2, C2),
    adj(R1, C1, R2, C2).

% 每个白格恰好从一个数字可达（防止岛屿被共享或无主）
:- white(R, C),
   #count { RootR, RootC : number(RootR, RootC, _),
                            white_reach(R, C, RootR, RootC) } != 1.

% 岛屿面积精确等于数字值
:- number(RootR, RootC, N),
   #count { R, C : white_reach(R, C, RootR, RootC) } != N.

% ===== 5. 海全体连通 =====
% 字典序最小的海格做种子
has_smaller_black(R, C) :- black(R, C), black(R2, C2), R2 < R.
has_smaller_black(R, C) :- black(R, C), black(R, C2), C2 < C.
min_black(R, C) :- black(R, C), not has_smaller_black(R, C).

% 从种子出发的可达性
reach_black(R, C) :- min_black(R, C).
reach_black(R2, C2) :-
    reach_black(R1, C1),
    black(R2, C2),
    adj(R1, C1, R2, C2).

% 每个海格都必须从种子可达
:- black(R, C), not reach_black(R, C).

% ===== 输出 =====
#show black/2.
```

## 7. 常见错误与调试

| 症状 | 原因与对策 |
|------|-----------|
| `unsafe variable` 报错 | 变量没有出现在正文字里。检查规则体是否缺少绑定该变量的条件 |
| 结果明显不对但 `SATISFIABLE` | 大概率漏了一条约束，或约束的变量范围写宽/写窄了。对照 6.4 的"删约束实验"思路，逐条注释掉约束看错误解何时出现 |
| 输出一大坨原子 | 忘了 `#show`。只输出关心的谓词 |
| 求解很慢 | 先 `--stats` 看是 Grounding 慢还是 Solving 慢；再 `--text` 检查接地规模。常见的坑：用两两比较写邻接（6.1），或选择规则里候选集合定义得过大 |
| 忘记句号 `.` | 每条语句（事实、规则、约束、`#show`）都以句号结尾，漏了会报解析错误 |
| 体里用 `;` 当"且" | `,` 才是且；`;` 在选择规则里是备选分隔符 |
| 把 `=` 当相等比较 | `=` 是赋值/合一，比较用 `==` |
| `not` 用过头 | `not` 是"无证据则假"，不是经典否定。依赖 `not` 的结论在新增事实后可能消失 |

调试心法：**一切推理都在规则里显式发生，没有隐藏状态**。程序输出不理解时，用 `--text` 看接地实例；候选太多了就加 `#show` 缩到最小复现；约束不生效就逐个删除定位——因为每条约束独立、可删可加，ASP 程序的调试比命令式代码更接近"搭积木"。

## 8. 回到仓库：AspSolver 怎么用这套程序

仓库里的 `AspSolver`（`src/Nurikabe/Nurikabe.Core/Solving/AspSolver.cs`）把上面第 6.6 节的完整程序以原始字符串内嵌在 `ConstraintsClingoCodeSnippet` 常量里，运行时：

1. `GenerateFacts(Grid)` 把 C# 的盘面对象转成 `dim/2`、`number/3`、`hollowed/2` 等事实字符串——坐标统一转成 1 基（C# 内部是 0 基平坦索引）；
2. 事实 + 约束代码拼接成完整程序；
3. 通过 P/Invoke 调用 libclingo（`ClingoControlAdd` → `Ground` → `Solve`），参数 `--models=0` 枚举全部解；
4. 解析每个回答集中的 `black/2` 原子，还原成 `CellMap` 海方块集合。

`Verify(Grid)` 取前 2 个解，数量为 1 则唯一；`Solve(Grid)` 取 1 个解（多于 1 个返回 `null`）。库缺失时静默返回空——求解失败与"无解"在调用方看来一致。所以命令行 `clingo` 和仓库的 `AspSolver` 用的是**同一份 ASP 程序**，本文所有示例都可以先在本机命令行验证，再对照 `AspSolver.cs` 看 C# 侧的拼接与解析。
